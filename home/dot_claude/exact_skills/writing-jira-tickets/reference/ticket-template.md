## Field defaults

| Field        | Default                                                        |
| ------------ | -------------------------------------------------------------- |
| parent       | the epic key (e.g. `PROJ-201`) — required, never guessed        |
| story points | **no default** — always proposed from the ACs and confirmed     |
| sprint       | asked, never assumed; blank = backlog                           |
| assignee     | asked, never assumed; blank = unassigned                        |
| labels       | asked, never assumed; offer what siblings use                   |
| priority     | `Medium`                                                        |
| issue type   | `Story` (feature) / `Task` / `Bug`                              |
| components   | empty unless siblings set one                                   |

Field IDs and value shapes live in [field-reference.md](field-reference.md).

## Worked example (PROJ-560)

**Title:** `Usage Dashboard - Include Region in Export Filename`

**Description:**

```markdown
The export filename generated by `buildExportFilename` in
`apps/reporting/utils/ExportHelper.ts` currently derives from only the report type,
date range, and account ID:

\```
`${reportType}-${dateRange}-${accountId}.csv`
\```

Because the deployment region (`REGION`) is not part of the filename, the same report
(e.g. `usage-2026-01`) exported from two regions produces identically named files.
For example, exporting from `eu.example.com` and `us.example.com` yields the same
filename, so downloads silently overwrite each other.

---

**Acceptance Criteria:**
**AC1:** The deployment region is included in the filename built by `buildExportFilename`.
**AC2:** The same report exported from two different regions (e.g. `eu` vs `us`) produces two different filenames.
**AC3:** Filenames remain deterministic for a given (report type, date range, account, region).
**AC4:** Existing `ExportHelper` unit tests are updated to cover the region dimension.
```

**Relationship:** linked to PROJ-176 via a real `Relates` issue link — **not** a text line
in the description.

> Note: the `\```` above are escaped only so this example renders inside a fence; use plain
> triple backticks in the real ticket.
