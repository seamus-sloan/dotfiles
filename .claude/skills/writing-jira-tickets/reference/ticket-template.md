## Worked example (ADA-560)

**Title:** `Mock Controller - Include Agency URL in Serial Number`

**Description:**

```markdown
The stable hardware serial number generated by `buildStableHardwareSerial` in
`fe/apps/e2e/mockControllerServer_v3/utils/HardwareGenerator.ts` currently hashes off
only the host seed, unit ID, device kind, and drone model:

\```
sha256(`${hostSeed}:${unitId}:${deviceKind}:${droneModel}`)
\```

Because the agency/connection URL (`BASE_URL`) is not part of the hash, the same unit
(e.g. `air-1`) on the same machine produces an identical serial number across
environments. For example, flying `air-1` on `qa2.ca.us.aerodome.com` and
`qa3.ca.us.aerodome.com` yields the same drone serial.

---

**Acceptance Criteria:**
**AC1:** The agency/connection URL is included in the hashed input of `buildStableHardwareSerial`.
**AC2:** The same unit on two different agency URLs (e.g. `qa2` vs `qa3`) produces two different serials.
**AC3:** Serials remain deterministic for a given (host, agency URL, unit, device kind, drone model).
**AC4:** Existing `HardwareGenerator` unit tests are updated to cover the agency-URL dimension.
```

**Relationship:** linked to ADA-176 via a real `Relates` issue link — **not** a text line
in the description.

> Note: the `\```` above are escaped only so this example renders inside a fence; use plain
> triple backticks in the real ticket.
```
